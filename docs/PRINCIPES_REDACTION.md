# Principes de rédaction

Les documents et l'interface de FRONTIÈRE sont rédigés pour une personne qui découvre le projet.

## Règles

1. Employer le français pour tous les titres, explications, consignes et libellés visibles.
2. Préférer une expression descriptive à une abréviation interne.
3. Expliquer un code avant de l'utiliser ; dans l'interface, afficher de préférence son sens en toutes lettres.
4. Éviter les termes de projet qui ne sont pas immédiatement compréhensibles hors de l'équipe.
5. Distinguer clairement un fait observé, une hypothèse, une interprétation et une décision.
6. Employer le même terme pour le même objet dans tous les documents.
7. Garder les noms techniques imposés par les langages, bibliothèques et services informatiques uniquement dans le code ou les commandes où ils sont nécessaires.

## Termes privilégiés

- « cas » pour une situation réelle étudiée ;
- « capacité nécessaire » pour ce qu'il faut savoir faire ;
- « ressource » pour la personne, l'équipe, l'organisme, l'outil ou l'infrastructure susceptible d'apporter cette capacité ;
- « voie de résolution » pour le mécanisme permettant de répondre au besoin ;
- « jeu de développement » pour les cas utilisés afin d'améliorer le système ;
- « jeu réservé » pour les cas conservés à part afin d'évaluer le système ;
- « valeur ajoutée » pour la différence attribuable à FRONTIÈRE sur le résultat, le délai, la qualité, le coût ou l'apprentissage ;
- « obstacle » pour un événement qui ralentit ou empêche la résolution d'un cas.

## Vérification

Une vérification automatique contrôle les principaux documents et modèles d'interface afin d'éviter la réintroduction de plusieurs termes anglais ou expressions internes déjà retirés.
