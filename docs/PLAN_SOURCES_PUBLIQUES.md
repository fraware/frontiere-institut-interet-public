# Plan de travail sur les sources publiques

## Objectif à six semaines

Construire un corpus suffisamment riche pour distinguer les difficultés de découverte, de vérification, de mobilisation, de fidélisation, de formation et d'infrastructure.

La cible est :

`100 signaux → 30 cas solides → 15 cas avec solution connue → 10 chronologies exploitables`

## Étape 1 — élargir les sources

Priorité aux rapports parlementaires, inspections générales, rapports d'opérateurs, documents budgétaires, concours et recrutements publics, marchés publics et rapports d'activité.

Chaque nouvelle source doit produire soit un cas, soit un contre-exemple, soit un constat de contexte clairement séparé.

## Étape 2 — approfondir les meilleurs cas

Pour les cas prioritaires, rechercher :
- la date d'apparition du besoin ;
- la capacité exacte ;
- les démarches entreprises ;
- la première ressource identifiée ;
- le moment où la capacité a été vérifiée ;
- le moment où elle a pu être mobilisée ;
- la première contribution utile ;
- le coût et le temps humain lorsqu'ils sont disponibles.

## Étape 3 — construire des comparaisons rétrospectives

Sur les cas dont la solution est connue, masquer la solution finale et reconstruire les informations disponibles au début du besoin. Comparer ensuite plusieurs méthodes de recherche sur les mêmes informations.

## Étape 4 — mesurer les chronologies

Séparer au minimum :
- le temps jusqu'à l'identification d'une ressource ;
- le temps entre cette identification et une contribution utile.

Cette distinction aide à déterminer si la difficulté principale concerne la recherche ou la mobilisation.

## Étape 5 — chercher les contre-exemples

Maintenir dans le corpus les situations où :
- la compétence existe déjà et est mobilisée rapidement ;
- une équipe ou un organisme public résout le besoin ;
- le recrutement fonctionne correctement ;
- la formation existante suffit ;
- aucune intervention supplémentaire n'est justifiée.

## Étape 6 — décider du prochain investissement technique

La version suivante du logiciel ne doit intégrer durablement une nouvelle source ou une nouvelle fonction que si plusieurs cas montrent qu'elle améliore la recherche, la vérification, la mobilisation ou la réutilisation.
